Procedures: parameters and return values

A procedure (also called a function or method) is a named group of instructions that may have parameters and may return a value.

AP exam pseudocode

PROCEDURE twice(n)
{
    RETURN(n * 2)
}
x ← twice(5)
DISPLAY(x)

MakeCode JavaScript

function twice(n: number): number {
    return n * 2
}
let x = twice(5)
  • Defining a procedure gives it a name. It does not run it. Calling it, as in twice(5), runs it.
  • A call interrupts the normal order. The program runs the statements inside the procedure, and when the last statement or a RETURN finishes, control goes back to the point just after the call.
  • Parameters are the input variables named in the definition (n). Arguments are the values supplied in the call (5). They are matched in order, so diff(10, 4) and diff(4, 10) can give different results.
  • RETURN(expression) ends the procedure right away and sends the value back. Use the returned value by storing it, displaying it, or using it in a bigger expression. A procedure can return from any branch.
  • The parameter holds a copy of the value. Changing it inside the procedure does not change the variable you passed in.

Why write procedures?

  • Procedural abstraction: a name for a process lets you use it knowing what it does, not how.
  • Modularity: a big problem is solved by combining solutions to smaller subproblems.
  • Fewer repeated lines, and easier-to-read code.
  • You can improve the inside of a procedure (make it faster, for example) without telling the people who use it, as long as it still does the same thing.
  • Parameters generalize a process so one procedure can handle many different values.

Libraries and extensions

Developers avoid rebuilding code that already exists. They share it in libraries.

  • A software library is a collection of procedures you can use to build new programs. A MakeCode extension is a library of blocks you can import into a project. You can also write your own extension and share it.
  • An application program interface (API) is the specification of how a library’s procedures behave and how to use them. The documentation tells you each procedure’s parameters and what it returns.
  • Using a library saves time because the code has already been written and tested. You rely on procedural abstraction: you use the procedure without knowing the details inside.
  • For example, randint(1, 6) is a library procedure. Its documentation says it takes a lowest and highest value and returns a random integer from the lowest to the highest, including both.

Logic: conditions, input, and loops

Complex conditionals combine true/false values so a program can make richer decisions.

  • Relational operators (= ≠ > < ≥ ≤) compare two values and evaluate to true or false. The logical operators NOT, AND, and OR combine true/false values.
  • Use parentheses so the order is clear: (x > 5) AND (y > 5).
  • De Morgan’s laws: NOT (a AND b) is (NOT a) OR (NOT b), and NOT (a OR b) is (NOT a) AND (NOT b).
  • A Boolean flag is a variable that holds true or false so one part of a program can tell another what happened.

Nested conditionals

An IF inside another IF only runs when the outer condition is true. When neither IF has an ELSE, these two programs do the same thing:

IF (hasKey)
{
    IF (level ≥ 3)
    {
        DISPLAY("open")
    }
}
IF (hasKey AND (level ≥ 3))
{
    DISPLAY("open")
}

Strings and user input

  • String concatenation joins strings end to end to make a new string.
  • Comparing strings with = is exact, so capital letters matter. “Arcade” and “arcade” are different.
  • Input from the user can be a string (such as a typed password) or a number. Your program should check, or validate, what it receives with a conditional before using it.

Logic in loops

A loop condition can use AND and OR too. In exam pseudocode, REPEAT UNTIL runs while the condition is false and stops when it becomes true. A MakeCode while loop is the opposite: it runs while the condition is true.

AP exam pseudocode

REPEAT UNTIL (lives = 0)
{
    // play one round
    lives ← lives - 1
}

MakeCode JavaScript

while (lives != 0) {
    // play one round
    lives -= 1
}

Multiplayer and tile maps

Two game-design ideas that put your logic and data skills to work.

Multiplayer

  • In a multiplayer game, each player has their own controller, sprite, and score or lives.
  • Programs compare the players’ values with conditionals and comparison operators to decide what happens, such as who is ahead or who wins. Chains of decisions use IF … ELSE IF … ELSE (in exam pseudocode, an IF nested inside an ELSE).

Tile maps

  • A tile map builds a scene from a grid of tiles. The map is data: each cell holds a tile type, so a map is a kind of grid of values.
  • Some tiles, such as walls, block sprites. Others are floors, goals, or hazards. Your code reacts when a sprite touches a tile type.
  • You can create your own tile images and edit the map to make levels.

Lists (arrays)

  
A list is an ordered sequence of values. One name holds many related values, which is a form of data abstraction: it manages complexity by letting you treat the whole collection as a single thing.

  
AP exam pseudocode
aList ← [10, 20, 30]
APPEND(aList, 40)
INSERT(aList, 2, 15)
REMOVE(aList, 4)
MakeCode JavaScript
let list = [10, 20, 30]
list.push(40)
list.insertAt(1, 15)
list.removeAt(3)

  
    
    
  • Each value is an element with an index. Exam lists start at index 1; MakeCode lists start at 0.
    • 
    
  • On the exam, an index below 1 or above LENGTH(aList) makes the program stop with an error.
    • 
    
  • APPEND adds to the end. INSERT puts a value at an index and shifts later values right. REMOVE deletes the value at an index and shifts later values left. The length changes each time.
    • 
    
  • aList[i] ← aList[j] copies the value at position j into position i.
    • 
    
  • Lists can hold numbers, strings, or other values. A list of strings might hold player names. A list of sprites lets one loop give every sprite the same behavior.
    • 
  

  
FOR EACH enemy IN enemies
{
    // every sprite in the list gets the same behavior
    moveToward(enemy, player)
}

    • 
    
  • FOR EACH item IN aList gives you each value, in order. It does not give you the index. Use REPEAT with an index variable when you need positions.

Algorithms with lists

  
Lists and iteration combine into a few patterns you will see again and again. Learn each pattern, then adapt it.

  
Sum and average

  
total ← 0
FOR EACH n IN nums
{
    total ← total + n
}
average ← total / LENGTH(nums)

  
Minimum or maximum

  
max ← nums[1]
FOR EACH n IN nums
{
    IF (n > max)
    {
        max ← n
    }
}

  
Start with the first element, not 0. If every value is negative, starting at 0 gives a wrong answer. For a minimum, flip the comparison to <.

  
Count how many match (frequency)

  
count ← 0
FOR EACH n IN nums
{
    IF (n = target)
    {
        count ← count + 1
    }
}

  
Linear (sequential) search

  
position ← 0
i ← 1

{
    IF (nums[i] = target)
    {
        position ← i
    }
    i ← i + 1
}

  
A linear search checks each element in order until it finds the value or has checked every element. It works on any list, sorted or not.

Sorting

  
Sorting puts data in order. Different algorithms can take the same input and produce the same output with different efficiency.

  

    
AlgorithmIdea

    
Bubble sortCompare neighbors and swap them if they are out of order. Repeat passes until nothing is out of order. Each pass moves the largest remaining value to the end.

    
Selection sortFind the smallest value in the unsorted part and swap it into the next position.

    
Insertion sortTake the next value and insert it into its place in the sorted part on its left.

  

  
REPEAT LENGTH(list) - 1 TIMES
{
    i ← 1
    REPEAT LENGTH(list) - 1 TIMES
    {
        IF (list[i] > list[i + 1])
        {
            temp ← list[i]
            list[i] ← list[i + 1]
            list[i + 1] ← temp
        }
        i ← i + 1
    }
}

  
Sorting matters because many tasks, such as binary search, only work on sorted data. Your class built a sorting algorithm to see this. The learning objectives for this part of the unit are about traversing lists and about efficiency, so focus on the ideas: sorted data enables faster searching, and algorithms for the same problem can differ in efficiency.

Searching: linear and binary

  
Binary search is often much more efficient than linear search, but it has a requirement.

  
    
    
  • Linear search checks each element in order until it finds the value or has checked them all.
    • 
    
  • Binary search starts at the middle of a sorted set of data and eliminates half of it. It repeats on the half that could still contain the value, until the value is found or nothing is left.
    • 
    
  • The data must be sorted for binary search to work.
    • 
    
  • Each check halves what is left, so the number of checks grows very slowly:
    • 
  

  

    
Values in the listMost checks, linear searchMost checks, binary search

    
15154

    
1001007

    
1,0001,00010

    
1,000,0001,000,00020

  

  
A range with an even number of values has two middle values, and different versions of binary search pick different ones. The counts in this guide are the same either way. The AP course treats specific binary search implementations as out of scope; what you need is what binary search requires, how it works, and how many values it checks.

A sorted list holds 2, 4, 6, 8, 10, 12, 14. A binary search looks for 11. How many values does it check before it can tell 11 is missing?

  

  
It checks 8, then 12 (the middle of 10, 12, 14), then 10. Nothing is left, so 11 is not in the list: 3 checks.



  

  
A sorted list has 1000 values. At most how many values does a binary search check?

  

  
Each check halves what is left: 1000, 500, 250, 125, 62, 31, 15, 7, 3, 1. That is at most 10 checks, instead of up to 1000 for a linear search.

Efficiency and problem solving

  
Computers can solve many problems, but not all of them, and not always in a reasonable amount of time.

  
    
    
  • A problem is a general description of a task. An instance is one specific input: sorting is a problem, and sorting the list (2, 3, 1, 7) is an instance of it.
    • 
    
  • A decision problem has a yes/no answer (“Is there a path from A to B?”). An optimization problem looks for the best solution among many (“What is the shortest path from A to B?”).
    • 
    
  • Efficiency estimates the computing resources an algorithm uses, usually as a function of the size of the input. Counting steps is one way to compare algorithms.
    • 
    
  • Algorithms with polynomial efficiency or lower (constant, linear, square, cube, and so on) run in a reasonable amount of time. Algorithms with exponential or factorial efficiency run in an unreasonable amount of time.
    • 
    
  • When no reasonable algorithm is known for the best answer, a heuristic can find a good solution in reasonable time. It may not be the best one.
    • 
  

  

    
How fast does the work grow?

    
Move the slider to change n, the size of the input, and compare how many steps each kind of algorithm needs. Large numbers are shown in scientific form.

    

    

  

  

  
A linear search checks up to n values. If the list becomes 10 times longer, the most checks it needs is multiplied by what number?

  

  
The worst case for a linear search grows in step with the list, so 10 times as many values means up to 10 times as many checks.



  

  
An algorithm needs about 2n steps for n items. Does it run in a reasonable or an unreasonable amount of time?

  

  
Exponential growth (and factorial growth) is unreasonable: each extra item doubles the work. Polynomial growth, such as n, n², or n³, is reasonable.

Simulations

  
A simulation is a representation that uses varying values to reflect the changing state of a phenomenon.

  
    
    
  • Simulations are most useful when real-world events are impractical for experiments: too big, too small, too fast, too slow, too expensive, or too dangerous.
    • 
    
  • They help people form and refine hypotheses.
    • 
    
  • A simulation can contain bias, because someone chose which real-world elements to include or leave out.
    • 
    
  • Many simulations use random numbers. RANDOM(a, b) returns a random integer from a to b, including both ends. Each result is equally likely.
    • 
  

  

    
Dice simulation

    
Roll one or two dice many times. Each die is RANDOM(1, 6).

    

    

    

  

  

  
How many different values can RANDOM(1, 6) return?

  

  
RANDOM(a, b) includes both ends, so it can return 1, 2, 3, 4, 5, or 6.

Undecidable problems

  
Can computers solve every problem? No.

  
    
    
  • An undecidable problem is one for which no algorithm can be built that is always capable of giving a correct yes-or-no answer.
    • 
    
  • An undecidable problem may have some instances that an algorithm can solve, but no algorithm can solve all of its instances.
    • 
    
  • The halting problem is a famous example: no algorithm can always decide, for every program and input, whether the program will finish or run forever.
    • 
    
  • “Undecidable” is different from “slow.” A slow problem can still be solved given enough time. An undecidable one cannot be solved by any algorithm, however long it runs. (Proving that a particular problem is undecidable is beyond this course.)
    • 
  

  

  
The halting problem is an example of an ____ problem. (one word)

  

  
No algorithm can always correctly decide, for every program and input, whether the program will finish or run forever.








  
Common traps

  

    
Students thinkWhat is true

    
The first element of a list is at index 0On the AP exam it is at index 1. In MakeCode it is at index 0. Convert carefully.

    
An index of LENGTH(aList) + 1 is fineIt is out of range. Valid indexes are 1 to LENGTH(aList), and a bad index stops the exam program with an error.

    
FOR EACH gives you the indexIt gives you each value, in order. Use an index variable if you need positions.

    
REMOVE leaves an empty spotIt shifts the later elements left and shortens the list by 1.

    
INSERT replaces the element at that indexIt shifts that element and the ones after it to the right and makes the list 1 longer.

    
Parameters and arguments are the same thingParameters are named in the definition. Arguments are the values supplied in the call.

    
A procedure always returns a valueOnly if it uses RETURN. A procedure can just do something, such as display values.

    
Changing a parameter changes the variable I passed inThe parameter holds a copy of the value. The original variable is unchanged.

    
Defining a procedure runs itDefining only names it. The code runs when the procedure is called.

    
REPEAT UNTIL runs while the condition is trueIt runs while the condition is false and stops when it becomes true. A MakeCode while is the opposite.

    
NOT (a AND b) is (NOT a) AND (NOT b)De Morgan: negate each part and switch the operator. It is (NOT a) OR (NOT b).

    
Starting max ← 0 always worksIf every value is negative, the answer stays 0. Start with the first element.

    
Binary search works on any listThe data must be sorted first.

    
Binary search checks every value, one at a timeIt checks the middle and eliminates half of what is left each time.

    
Reasonable time means fastIt means polynomial or lower. Exponential and factorial growth are unreasonable.

    
A heuristic always finds the best answerIt finds a good answer in reasonable time but may not be the best.

    
Undecidable means very slowIt means no algorithm can always give a correct yes-or-no answer, however much time it has.

    
A simulation is always accurateIt can contain bias from what was included or left out.
