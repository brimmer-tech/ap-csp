Algorithms, flowcharts, and debugging

  
An algorithm is a finite set of instructions that accomplishes a specific task. Every algorithm is built from three kinds of steps.

  

    
ImplementationMeaningFlowchart shapeArcade example

    
Sequencingsteps run in order, one after anotherrectangle (process)set x then change score

    
Selectiona condition decides which steps rundiamond (decision)if score > 10 then … else …

    
Iterationsteps repeat a set number of times or until a condition is metarrow looping backrepeat 4 times, while

  

  
    
    
  • Two algorithms written differently can produce the same result. Two that look almost identical can produce different results or side effects; order matters.
    • 
    
  • New algorithms are built from an idea, by combining existing algorithms, or by modifying one. Reusing tested algorithms saves development time and testing.
    • 
    
  • Program documentation describes what code does and how it was developed; comments are documentation written inside the program and do not change how it runs. Document throughout development, not only at the end.
    • 
    
  • Debugger mode in MakeCode steps through blocks one at a time so you can watch variable values change.
    • 
    
  • Testing means running the program with chosen inputs to confirm it produces the expected outputs.
    •

Sprites, events, and the screen

  
The Arcade screen is 160 pixels wide by 120 pixels tall. x runs 0 to 159 left to right; y runs 0 to 119 top to bottom, so a bigger y is lower on the screen. The center is about (80, 60).

  
    
    
  • A sprite is an image with a position, velocity, and a kind (Player, Enemy, Food, Projectile). Kinds let on overlap events tell sprites apart.
    • 
    
  • An event is something that happens: A button pressed, two sprites overlap, the game starts. An event handler is the block that waits for that event and runs its inside code when it fires.
    • 
    
  • on start runs once when the program loads. on A button pressed runs every time A is pressed. on game update runs over and over, every frame.
    • 
    
  • Velocity is speed with direction: vx positive moves right, negative moves left; vy positive moves down, negative moves up. move mySprite with buttons sets velocity from the d-pad.
    • 
    
  • Program input is data sent to the program (button presses, ask for number). Output is data the program sends out (sprite say, splash, score, sound).
    • 
  

  

    
MakeCode blocks

      

        on A button pressed
        

          set mySprite position to x 80 y 60
          change score by 1
        

      

    
AP pseudocode has no events; the exam shows the handler body as a procedure

    SET_POSITION(mySprite, 80, 60)
    score ← score + 1
}

      on B button pressed

A sprite has vx = 40 and vy = -40. Which way does it travel? (up and to the right / up and to the left / down and to the right / down and to the left)

    

    
Positive vx is rightward. Negative vy is upward, because y grows downward on the screen.

  






  
Variables, data types, and expressions

  
A variable is a named container that holds one value at a time; set replaces the value and change by adds to it.

  

    
TypeExamplesArcade blocks

    
Number0, 42, -3, 2.5Math category (purple): + − × ÷, remainder of, pick random

    
String"Hello", "20" (text, not a number)Text category: join, length of, parse to number

    
Booleantrue, falseLogic category (blue): comparisons, and, or, not

    
SpritemySpriteSprites category: a variable that holds a sprite object

  

  
    
    
  • An expression is anything that evaluates to a single value: 5, score, score + 1, bill × 0.2.
    • 
    
  • set score to score + 1 and change score by 1 do the same thing. Assignment copies the value at that moment; later changes to the right side do not update it.
    • 
    
  • String concatenation joins strings end to end: join("Score: ", score) gives "Score: 7". A number inside a string is text; "3" + "4" joined is "34", not 7.
    • 
    
  • ask for number and ask for string are inputs. In the 20% Tip App: tip ← bill × 0.20, total ← bill + tip, then splash(join("Total: ", total)).
    • 
    
  • A substring is part of a string; an index is a position number used to reference a character or list element. (AP pseudocode lists start at index 1.)
    • 
  

  

    
What is b at the end?

    
a ← 5
b ← a
a ← a + 10
b ← b + 2

    

    
b copied 5 from a. Changing a afterward does not change b. Then b becomes 7. (a is 15.)

  

  

    
The user enters 20 for the bill. What does the splash show?

    

      set bill to ask for number "Bill?"
      set tip to bill × 0.2
      set total to bill + tip
      splash join "Total: " total
    

    

    
tip = 20 × 0.2 = 4; total = 24; join puts the text and the number together.

  






  
Booleans, relational operators, and conditionals

  
A conditional runs its inside code only when its Boolean condition is true; else runs when it is false, and a nested conditional is one if placed inside another.

  

    
RelationalReads asLogicalTrue when

    
= (== in JS)equal toA and Bboth are true

    
≠not equal toA or Bat least one is true

    
> <greater / less thannot AA is false

    
≥ ≤greater / less than or equal

  

  
    
    
  • Relational operators compare two values and produce a Boolean. score > 10 is either true or false; it is not a number.
    • 
    
  • if / else if / else: only the first true branch runs. Order the checks from most specific to least.
    • 
    
  • Nested: if hasTicket then (if age ≥ 18 then adult else child). The inner if is only reached when the outer one is true.
    • 
    
  • not (a = b) is the same as a ≠ b. not (x > 5) is x ≤ 5, not x < 5.
    • 
    
  • In on overlap events, the sprite kinds are a built-in selection: the code only runs for the kinds you chose.
    •

grade is 85. What letter is displayed?

x is 7 and y is 3. Is this expression true or false?

    
(x > 5) AND (NOT (y < 5))

    

    
x > 5 is true. y < 5 is true, so NOT of it is false. true AND false is false.

    ELSE { DISPLAY("child") }

The outer condition is true, so the inner conditional runs. 12 ≥ 18 is false, so the inner else prints child.

  






  
Random numbers and the modulus operator

  
pick random 1 to 6 (AP: RANDOM(1, 6)) returns a whole number from 1 to 6, including both ends. A coin flip is RANDOM(0, 1) or RANDOM(1, 2). Computers produce pseudo-random numbers from a formula and a seed, which is why they only look random.

  
Modulus (remainder of a ÷ b, AP: a MOD b) gives the remainder after whole-number division. 17 MOD 5 is 2. It is the standard test for even and odd (n MOD 2 = 0 means even) and for wrapping a value around a range.

  

    
Modulus explorer

    

    

    

    
Groups of b are filled first; the leftover squares are the remainder.

  

  

    
Random range checker

    

    

  

  

    
What is 23 MOD 4?

    

    
4 goes into 23 five times (20), leaving 3.

  

  

    
How many different values can RANDOM(5, 10) produce?

    

    
5, 6, 7, 8, 9, 10: both ends included, so 10 − 5 + 1 = 6 values.

  

  

    
n is 31. Does this display even or odd?

    
IF (n MOD 2 = 0) { DISPLAY("even") }
ELSE { DISPLAY("odd") }

    

    
31 MOD 2 is 1, not 0, so the else branch runs.

  






  
Loops and animation

  
Iteration repeats a block of code either a set number of times or until a condition becomes true, and it replaces copy-pasted blocks with one block that runs many times.

  

    
Arcade blockAP pseudocodeNotes

    
repeat 4 timesREPEAT 4 TIMES { }runs exactly 4 times

    
while <condition>REPEAT UNTIL (condition) { }opposite senses: while runs while true; REPEAT UNTIL runs while false and stops when true

    
for index from 0 to 4(no direct form)index takes 0, 1, 2, 3, 4: that is 5 iterations, because MakeCode includes the end value

    
on game update every 500 ms(event)a loop driven by time; used for animation frames and spawning

    
foreverREPEAT UNTIL (false)never stops on its own

  

  
    
    
  • Animation is iteration: change the sprite’s image (or position) a little, pause, repeat.
    • 
    
  • A loop that never reaches its stopping condition is an infinite loop. REPEAT UNTIL (x = 10) with x ← x + 3 starting at 0 never hits exactly 10.
    • 
    
  • To trace a loop, make a table with one row per pass: the index or counter, and each variable’s value after the pass.
    • 
  

  

    
Blocks

      

        set total to 0
        for index from 0 to 3
        
change total by index

      

    
AP pseudocode

      
total ← 0
i ← 0
REPEAT UNTIL (i > 3)
{
    total ← total + i
    i ← i + 1
}

  

  

    
What is total after the loop above finishes?

    

    
index runs 0, 1, 2, 3 (four passes). 0 + 1 + 2 + 3 = 6.

  

  

    
How many times does DISPLAY run?

    
count ← 10
REPEAT UNTIL (count < 1)
{
    DISPLAY(count)
    count ← count − 2
}

    

    
Displays 10, 8, 6, 4, 2 (five times). Then count is 0, 0 < 1 is true, and the loop stops.

  

  

    
What is x at the end?

    
x ← 3
REPEAT 3 TIMES
{
    x ← x × 2
}

    

    
3 → 6 → 12 → 24.

  






  
Projectiles

  
A projectile is a sprite of kind Projectile that is created with a velocity and is automatically destroyed when it leaves the screen, so you do not have to clean it up. projectile from mySprite with vx 50 vy 0 starts at the sprite’s position; projectile from side with vx -50 vy 0 starts at the screen edge and moves left.

  
    
    
  • Positive vx flies right, negative flies left. Positive vy falls down, negative rises. Larger numbers move faster (pixels per second).
    • 
    
  • Projectiles are usually created inside an event (on A button pressed) or a timed loop (on game update every 300 ms) so they keep coming.
    • 
    
  • In Task 2b you put the create projectile block in a for index loop so 13 meteors were made at once, each starting lower by using index in the position: one block instead of thirteen.
    • 
    
  • on overlap Player with Projectile is how a hit is detected: a selection event keyed on sprite kinds.
    • 
  

  

    on game update every 300 ms
    

      set meteor to projectile from side with vx 0 vy 50
      set meteor x to pick random 0 to 159
    

  

  

    
In the blocks above, which direction do the meteors move? (up, down, left, right)

    

    
vx is 0 and vy is positive 50, so they fall straight down from a random x.

  

  

    
A for index from 0 to 12 loop contains one create projectile block. How many projectiles are created each time the loop runs?

    

    
MakeCode’s for loop includes the end value: 0 through 12 is 13 passes.
